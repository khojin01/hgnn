# 옵시디언 · 클로드 · 디스코드 사용 설명서

dms2 서버에서 하이퍼그래프 벤치마크(HyperGC, KDD '26)를 재현한다.
실험은 서버가 돌리고, 기록은 자동으로 쌓이고, 사람은 세 창구로 본다.
이 문서는 그 셋이 어떻게 이어져 있고 무엇을 어디서 하면 되는지 설명한다.

---

## 1. 한 장으로 보는 구조

```
                    dms2 서버 (모든 것의 원본)
                    실험 · 결과 파일 · 노트 · 1분마다 도는 파이프라인
                                 │
        ┌────────────────────────┼────────────────────────┐
        │                        │                        │
    GitHub 경유              세션이 발행               서버가 직접
        │                        │                        │
   옵시디언 (로컬 PC)      아티팩트 2개 (웹)          디스코드
   노트를 읽고 쓴다        표와 현황을 본다          알림 · 조회 · 지시
```

**원본은 언제나 서버다.** 옵시디언은 거울이고, 아티팩트는 사진이고, 디스코드는 전령이다.
어느 창구에서 보든 같은 파일을 보고 있다.

### 1분마다 도는 것

서버의 `tools/refresh_all.sh` 하나가 cron 으로 1분마다 돌며 순서대로 한다.

| 순서 | 하는 일 |
|---|---|
| 1 | 실험 결과 파일을 읽어 결과 원장(`experiment_now.md`)을 갱신 |
| 2 | 원장을 구조화해 `state.json` 으로, 논문 기준값과 대조 |
| 3 | 논문 대조 리포트 HTML 생성 |
| 4 | 옵시디언 노트와 `live.json` 생성 |
| 5 | 디스코드에 상태 변화 알림, 봇이 죽었으면 되살림 |
| 6 | 내용이 바뀐 노트만 커밋·푸시 |

순서가 곧 의존 관계다. 전부 합쳐 0.3초쯤 걸린다.
어디서 멈췄는지는 `dashboard/pipeline.log` 를 본다.

## 2. 옵시디언 — 연구 노트

로컬 PC 의 옵시디언이 서버의 `vault/` 를 git 으로 미러한다.
작업 스케줄러가 1분마다 GitHub 의 최신 커밋을 확인하고, 새 커밋이 있을 때만 받아온다.

### 무엇이 있나

```
vault/
  Home.md                          시작 화면
  knowledge/   논문 대조 · models/ · datasets/ · 에이전트
  protocols/   실행 규약 · <모델> 실행
  lab/         일지/ · 다음 할 일 · 질문
```

### 고쳐도 되는 것과 안 되는 것

| | 고쳐도 되나 | 이유 |
|---|---|---|
| `lab/` 전체 | **된다** | 사람과 클로드가 같이 쓴다 |
| `protocols/` 의 **함정과 판단** 아래 | **된다** | 실험하며 알게 된 것을 쌓는 자리 |
| `knowledge/` 전체 | 안 된다 | 1분마다 자동으로 덮어쓴다 |
| 모든 노트의 `AUTO:BEGIN ~ AUTO:END` | 안 된다 | 같은 이유 |

자동 구간을 고쳐도 다음 1분에 사라진다. 화가 나는 일이니 미리 알아두면 좋다.

### 결과 수치는 손으로 적지 않는다

실험이 끝나면 `results/*.txt` 에 남고, 파이프라인이 알아서 원장과 노트로 올린다.
노트에 직접 숫자를 적으면 다음 갱신 때 덮어써지거나 원장과 어긋난다.

### 로컬에만 있는 것

옵시디언 볼트의 `papers/` 는 사람의 논문 공부 기록이라 저장소에 없다. 서버와 무관하게 자유롭게 쓴다.

## 3. 아티팩트 — 웹에서 보는 현황

로그인만 하면 어디서든 열린다. 휴대폰에서도 된다. **두 개가 짝이다.**

| 아티팩트 | 무엇을 보나 |
|---|---|
| [HGNN MAIN](https://claude.ai/artifact/CmR71CY6fS8EVtFD8Ce3pY) | 실행 상태 · 에이전트 · 연구 노트 · 지시 · 커밋 알림 |
| [HyperGC 재현 대조(dms2)](https://claude.ai/artifact/McC9c6qoLCw13GmFBqvZkb) | Table 3·4·5 를 칸 단위로 논문과 대조 |

### 스냅샷이지 실시간이 아니다

아티팩트 페이지는 보안 정책상 바깥으로 네트워크 요청을 못 한다. 그래서 서버에 직접 물어볼 수 없고,
클로드 세션이 그때그때 데이터를 심어 발행한 **사진**이다. 페이지 위쪽에 찍힌 시각이 그 사진의 시각이다.

실시간이 필요하면 디스코드 봇에게 물어보는 게 맞다 (아래 4장).

### 관제 페이지에서 할 수 있는 일

- **연구 노트 탭** — 할 일 체크·수정·삭제, 일지 편집. 저장하면 세션이 서버 파일에 반영한다.
- **지시 탭** — 클로드에게 시킬 일을 적는다. 보내는 순간 페이지가 스스로 다시 발행되어 세션을 깨운다.
- **커밋 알림 탭** — 서버·GitHub·로컬 PC 세 HEAD 가 같은지 본다. 지난 방문 뒤 쌓인 커밋에 NEW 가 붙는다.

### 갱신은 세션만 할 수 있다

서버는 1분마다 두 HTML 파일을 다시 만들지만, 그걸 claude.ai 에 올리는 일은 클로드 세션만 할 수 있다.
**둘 중 하나만 올리면 다른 하나가 조용히 낡는다.** 실제로 대조 아티팩트가 이틀 낡았던 적이 있다.

## 4. 디스코드 — 알림과 조회와 지시

서버가 직접 말하는 창구다. 클로드 세션이 없어도 돌아간다.

### 먼저 말을 거는 것 (알림)

실험이 시작되거나, 데이터셋 하나가 끝나거나, OOM·타임아웃으로 막히거나, 실패하거나,
자동화가 멈추면 카드로 알려준다. 색으로 구분한다.

| 색 | 뜻 |
|---|---|
| 파랑 | 실험 시작 |
| 초록 | 완료 |
| 주황 | 자원 한계 (OOM · 타임아웃) |
| 빨강 | 실패 |

직전 상태와 비교해 바뀐 것만 보내므로 같은 소식이 반복되지 않는다.

### 물어보는 것 (조회)

채널에 이렇게 치면 봇이 답한다.

| 명령 | 답 |
|---|---|
| `@상태` | 지금 무엇이 돌고 있나 |
| `@gpu` | GPU 사용률 — **스냅샷이 아니라 지금 값** |
| `@실행` | 최근 실행 요약 |
| `@todo` | 열린 할 일 |
| `@논문` | 논문 대조 요약 |
| `@도움말` | 쓸 수 있는 말 전부 |

`@gpu` 가 0% 로 나오면 왜 0% 인지 한 줄이 따라붙는다. 못 읽은 건지 정말 쉬는 중인지 구별하려는 것이다.

부르는 말은 바꿀 수 있다. 서버의 `.discord.json` 에 `commands` 를 넣으면 된다.
왼쪽 기능 이름은 고정이고 오른쪽 목록만 바꾼다. 빈 목록으로 두면 그 기능이 사라진다.

```json
"commands": {
  "status": ["@상태", "@ㅅㅌ"],
  "gpu": ["@gpu"],
  "journal": []
}
```

봇을 다시 띄울 필요 없다. 메시지마다 설정을 다시 읽는다.

### 시키는 것 (지시)

```
@지시 TriCL House 편차 원인 확인 — num_edges 확장 방식부터
```

봇이 받아서 서버의 지시함(`dashboard/inbox.jsonl`)에 넣는다.
클로드 세션이 깨어 있으면 20초 안에 가져가고, 없으면 다음에 열릴 때 가져간다.

진행 상황과 결과는 `#order` 채널로 보고가 온다.

### 누가 보냈는지 가린다

설정의 `owner` 에 적힌 디스코드 계정이 보낸 지시만 바로 수행 대상이다.
다른 사람이 같은 채널에서 `@지시` 를 써도 기록만 남는다. 나중에 누굴 초대해도 안전하다.

---

## 5. 지시가 흐르는 길

두 갈래로 들어오지만 **한 곳에 모인다.**

```
디스코드 @지시 ────────────────┐
                              ├──→ dashboard/inbox.jsonl ──→ 클로드가 처리 → done 으로 닫음
관제 페이지 지시함 → 세션을 깨움 ┘
```

지시함이 유일한 기록이다. 처리한 것은 닫고, 닫지 않으면 계속 미처리로 남아 다음 세션이 다시 본다.

### 어느 쪽이 빠른가

| 경로 | 닿는 시간 |
|---|---|
| 클로드와 직접 대화 | 즉시 |
| 관제 페이지 지시함 | 즉시 (페이지가 세션을 깨운다) |
| 디스코드 `@지시` | 세션이 지켜보고 있으면 20초, 아니면 다음 세션 |

### 절대 하지 않는 것

**채팅에 적은 글이 셸 명령이 되는 구조는 없다.** 어느 경로든 글은 파일에 적힐 뿐이다.
실험을 시작할지 멈출지는 클로드가 실행 규약을 읽고 판단해서 한다.
웹 폼이나 채팅 입력을 그대로 서버에서 실행하면 그 창구를 아는 누구나 서버를 조작할 수 있게 된다.

## 6. 자주 하는 일

### 지금 실험이 돌고 있나

디스코드에 `@상태`. 또는 관제 페이지 실행 상태 탭.

### 결과가 논문과 얼마나 다른가

논문 대조 아티팩트. 칸마다 Δ(우리 값 − 논문 값)가 붙는다.
±2 이내는 초록, 2~5 는 주황, 5 초과는 빨강이다.

### 클로드에게 일을 시키고 싶다

밖에 있으면 디스코드 `@지시`. 자리에 있으면 관제 페이지 지시함이나 직접 대화.

### 실험이 밤새 어떻게 됐는지 보고 싶다

디스코드 알림이 이미 와 있다. 자세한 것은 옵시디언의 `lab/일지/<날짜>.md`.

### 노트를 고치고 싶다

옵시디언에서 직접 고친다. 밖이면 관제 페이지 연구 노트 탭.
둘 다 `lab/` 안에서만 고친다. `knowledge/` 와 `AUTO` 구간은 덮어써진다.

## 7. 안 될 때

| 증상 | 먼저 볼 곳 |
|---|---|
| 디스코드 알림이 안 온다 | `dashboard/pipeline.log` 가 1분마다 갱신되는지. 봇 프로세스가 사는지 |
| 봇이 말에 반응이 없다 | 첫 단어가 `@` 로 시작하는지. 봇이 그 채널을 볼 권한이 있는지. 개발자 포털의 MESSAGE CONTENT INTENT 가 켜져 있는지 |
| `@지시` 를 보냈는데 답이 없다 | 봇 답("받았다")은 오는지. 온다면 서버까지는 갔고 세션이 없는 것이다 |
| 옵시디언 노트가 안 바뀐다 | 관제 페이지 커밋 알림 탭에서 세 HEAD 가 같은지 |
| 아티팩트가 낡았다 | 클로드에게 갱신을 부탁한다. 서버는 파일까지만 만든다 |
| 결과를 냈는데 표에 안 올라온다 | 파일 이름이 `result_<데이터셋>_<모델>_<태스크>.txt` 인지. 20 seed 배열과 평균±표준편차가 한 쌍으로 들어 있는지 |

### 재시작 뒤에 되살아나는 것과 아닌 것

| | 되살아나나 |
|---|---|
| 서버 파이프라인 (cron) | **된다** |
| 디스코드 봇 | **된다** (파이프라인이 매분 확인) |
| 웹 대시보드 :8765 | **된다** (`@reboot` cron) |
| 로컬 PC 의 git 동기화 | **된다** (작업 스케줄러) |
| 클로드 세션의 감시 | **안 된다** — 로컬에서 `bin/hgnn_watch.sh` 를 다시 켜야 한다 |

마지막 줄이 중요하다. 로컬 PC 를 재시작하면 지시를 지켜보던 감시가 죽는다.
지시는 지시함에 그대로 쌓이므로 사라지지는 않지만, 다시 켜기 전까지 아무도 가져가지 않는다.

## 8. 설정 파일

| 파일 | 무엇 | 저장소에 |
|---|---|---|
| `.discord.json` | 웹훅 · 봇 토큰 · 채널 · owner · 보고 채널 · 명령어 | 안 들어간다 |
| `.agents/*.md` | 에이전트 역할 정의 | 들어간다 |
| `vault/protocols/` | 실행 규약과 모델별 명령 | 들어간다 |
| `CLAUDE.md` | 클로드가 이 저장소에서 지킬 규칙 | 들어간다 |

토큰이 든 파일은 권한 600 이고 `.gitignore` 에 있다. GitHub 에 올라가지 않는다.

## 9. 도구 한눈에

서버의 `tools/` 에 있는 것들이다. 전부 `refresh_all.sh` 나 클로드가 부른다.

| 도구 | 하는 일 |
|---|---|
| `refresh_all.sh` | 1분마다 도는 파이프라인 전체 |
| `vault_build.py` | 옵시디언 노트와 `live.json` 생성 |
| `pulse.py` | 상태를 한 줄로 요약 — 세션이 깨어날지 판단하는 신호 |
| `inbox.py` | 지시함 — 넣고 · 보고 · 닫는다 |
| `note_write.py` | 아티팩트에서 고친 노트를 파일에 반영 |
| `discord_bot.py` | 알림 · 조회 · 지시 |
| `cluster_eval.py` | 커뮤니티 탐지(Table 5) 평가 — 임베딩을 k-means 로 군집해 NMI |

로컬 PC 의 `bin/` 에는 둘이 있다.

| 도구 | 하는 일 |
|---|---|
| `hgnn_build.py` | 아티팩트 두 개의 HTML 을 한 번에 받아 온다 |
| `hgnn_watch.sh` | 지시와 상태 변화를 지켜보다 세션을 깨운다 |
